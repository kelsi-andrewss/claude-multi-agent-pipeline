Bottom line: The system records and displays corrections reliably. But the "learning" part — where corrections influence decisions, bias model selection, or generate enforcement hooks — is entirely non-functional. What exists is self-documenting, not self-learning. The LLM reads a text file; there's no feedback loop that actually conditions behavior beyond prompt injection.

What Gets Fixed

  • Create decision_preferences table in schema migration
  • Stage 2 signal processing becomes functional
  • mkdir compliance/ in Stage 5 before writing hooks
  • Hook generation pipeline produces real hooks
  • Penalized decisions rendered into session context
  • Decision scores shown alongside trust calibration

Deliberately Dropped

  • Temporal fact graph — no clear consumer, adds complexity with no feedback path
  • Complex signal_score → model selection override — trust scores already handle this
  • Hook blocking mode — warn-only is safer, avoids false positive lockouts
The refactor scope is small: 3 fixes (create table, create directory, render scores) close the loop from self-documenting to self-conditioning. The existing code for Stage 2 and Stage 5 is already written and correct — it just needs its prerequisites to exist. The new component (decision score rendering) is ~30 lines of Python in the session-start hook.

What "self-learning" actually means here: The LLM can't update its weights. What it can do is condition future behavior through three mechanisms: text injection (preferences in context), structural guardrails (hooks that warn before bad patterns), and statistical bias (decision scores that surface which choice patterns led to corrections). The refactor closes all three channels.
