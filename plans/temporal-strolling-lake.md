# Fix end-to-end chat flow (Flutter ↔ Python backend)

## Context

The Flutter app shows "Something went wrong" on every message despite the backend returning 200 OK. Multiple issues compound: a field name mismatch between backend and frontend, `dart:io` incompatibility with Flutter web, and the LangChain agent using an unreliable agent type. These fixes were made on epic branches previously but never merged to master.

## Issues (ordered by severity)

### 1. `dart:io` crashes on Flutter web
**File:** `advocate/flutter/lib/services/advocate_api.dart`
- Uses `dart:io` `HttpClient` — not supported on Flutter web, crashes silently
- `package:http` is not in `pubspec.yaml`
- **Fix:** Add `http: ^1.2.0` to `pubspec.yaml` dependencies; rewrite `advocate_api.dart` to use `package:http` instead of `dart:io`

### 2. Field name mismatch: `response` vs `reply`
**Files:** `advocate/flutter/lib/shared/models/session.dart`, `advocate/main.py`
- Python sends `{"response": "..."}`, Flutter reads `json['reply']` → always null
- `chat_provider.dart:63` does `session.reply ?? ''` → empty string → error path
- **Fix:** Change `session.dart:23` to read `json['response']` instead of `json['reply']`

### 3. `create_structured_chat_agent` → `create_tool_calling_agent`
**File:** `advocate/agent.py`
- `create_structured_chat_agent` produces "Invalid or incomplete response" spam with Gemini
- The fix to `create_tool_calling_agent` was on an orphaned branch, never merged
- Also: memory variable name should be `chat_history` (matches the MessagesPlaceholder), and session state should be injected as HumanMessage/AIMessage pair instead of SystemMessage
- **Fix:** Switch to `create_tool_calling_agent`, update imports, fix memory injection

## Changes

### A. `advocate/flutter/pubspec.yaml`
Add under `dependencies:`:
```yaml
  http: ^1.2.0
```

### B. `advocate/flutter/lib/services/advocate_api.dart`
- Replace `import 'dart:io';` with `import 'package:http/http.dart' as http;`
- Rewrite `_doPost` to use `http.post()` returning `http.Response`
- Rewrite `streamMessage` to use `http.StreamedRequest` (or remove if unused)
- Remove `_HttpResponse` helper class

### C. `advocate/flutter/lib/shared/models/session.dart`
- Line 23: `reply: json['response'] as String?,` (was `json['reply']`)

### D. `advocate/agent.py`
- Import: `create_tool_calling_agent` instead of `create_structured_chat_agent`
- Import: `HumanMessage, AIMessage` from `langchain_core.messages`
- Line 170: `create_tool_calling_agent(...)` instead of `create_structured_chat_agent(...)`
- `SessionAwareMemory.load_memory_variables`: inject state as HumanMessage/AIMessage pair
- Memory variable name: `memory_key="chat_history"` in `ConversationBufferWindowMemory`
- Remove `max_execution_time=60` (causes premature "Agent stopped" errors)

### E. `advocate/flutter/pubspec.lock`
Will be regenerated by `flutter pub get` after pubspec.yaml change.

## Verification

1. Run `cd advocate/flutter && flutter pub get` — must succeed
2. Run `cd advocate/flutter && flutter build web` — must compile without errors
3. Start backend: `set -a && source advocate/.env && set +a && advocate/venv/bin/python -m uvicorn advocate.main:app --reload --port 8000`
4. Open Flutter web app, sign in, send a chat message
5. Verify: backend logs show successful agent execution (no "Invalid or incomplete response" spam)
6. Verify: Flutter displays the agent's actual response text, not "Something went wrong"
7. Verify: session_id is returned and reused on subsequent messages
